# PR Forge — Product, functionality & design audit

Audit #1 of the "Claude Product Audit & Improvement Prompt Pack", 24 November 2026, against app 2.0.1 (`main` at `ef36434`). No code was changed for this audit.

**Evidence labels.** *Confirmed* = reproduced in the running app (headless Chromium at 375×667 / 390×844 with realistic data) or proven by a test script or the code. *Likely* = follows from the code but not reproduced. *Unverified* = depends on something outside the repo (Supabase, Google, iOS).

## 1. Executive assessment

PR Forge is a good personal logger: fast set entry (one tap per set when last time's numbers are right), honest plain-word trends, real offline use, cloud backup, and a recent visual pass that looks deliberate. Calculations held up in the 17 Nov review and the four bugs found then are fixed.

What stops it being a product a serious lifter chooses over Strong or Hevy today:

1. **Trust gaps at the edges.** Two phones editing routines at the same time silently lose one phone's changes. The sign-in page says "continue to pvtcqdtqycihlontmirl.supabase.co", which users told you feels sketchy. A 99,999 lb typo is accepted and celebrated as a PR.
2. **The PR system misses the PRs lifters care about most.** For weighted lifts only a higher *estimated 1RM* counts. One more rep at the same weight, or the heaviest weight you've ever moved, often goes unrecognised.
3. **The logging card is crowded.** The open exercise has up to eight buttons under the sets (your hammer curl screenshot shows seven), on the screen where speed matters most.
4. **First run asks too much of a beginner.** There are no starter routines, so a new user must design a program before logging a set.
5. **No safety net in the process.** No CI: tests only run when someone runs them, and every merge goes straight to every user.

None of these needs a rebuild. Most are small, contained changes.

## 3. Confirmed bugs and deficiencies

| # | Problem | Evidence | Severity |
|---|---|---|---|
| B1 | **Profile sync loses changes.** Routines, custom exercises, settings, pins, body weight, logging types and sides are synced as one blob. If two devices both change it before syncing, the last one to sync wins and the other's changes vanish on both devices. | Reproduced with the sync engine: phone A adds "Made on phone A", phone B adds "Made on phone B", both sync → both phones and the cloud keep only B's routine. `js/sync.js` `mergeProfile` ("this phone's version wins"). Workouts are synced row by row and are not affected. | **High** (silent data loss) |
| B2 | **Sign-in shows the Supabase address.** | Kevin's screenshot, 23 Nov; users call it sketchy. | **High** (trust, sign-ups) |
| B3 | **Implausible numbers accepted and celebrated.** | 99999 lb × 5 → "New personal record … 116665.5 lb est. 1RM". "1e5" stored as 100000. `parseNum` in `js/app.js` has no upper bound and accepts exponents. | Medium |
| B4 | **PRs only on estimated 1RM for weighted lifts.** A rep PR at the same weight, or a heaviest-ever weight, isn't celebrated unless it also beats the best e1RM. | `js/metrics.js` `checkPr` returns only `e1rm`, `reps` (bodyweight) or `seconds`. | Medium (core value) |
| B5 | **Rest timer lost on close/reopen.** | Rest dock present → reload → gone (`V.rest` lives in memory only). | Medium |
| B6 | **Workout in progress is local only.** Lost if the phone's storage is wiped mid-session. | `S.active` isn't synced. Deliberately deprioritised 17 Nov. | Low |
| B7 | **Custom exercises can't change muscle or equipment.** | Exercise page offers Rename/Delete only. | Low–Medium |
| B8 | **Settings keeps the previous tab highlighted.** | Screenshots 18 Nov. | Low |
| B9 | **Storage ceiling.** ~1.8 KB per workout in browser storage (~5 MB on iPhone) → roughly 2,500 workouts including imports before saves fail. The app warns when a save fails. | Measured: 34 workouts = 62 KB. | Low now, grows |
| B10 | **No CI.** Tests (55, all passing) run only by hand; every merge deploys to everyone. | No `.github/workflows`. | Medium (process) |
| B11 | **Open security chore:** the Google client secret pasted in chat on 2 Nov hasn't been rotated. | CLAUDE.md to-do. | Medium |

## 4. Architecture and data flow

```
index.html ─ loads ─ units · exercise-library · exercises · metrics · store · plates · importers · supabase · sync · cloud · app

Tap / type ─► js/app.js action handlers ─► S (state: workouts, active, templates, settings, customs, bodyWeights)
                    │                            │
                    │ render(): one view function per screen, HTML strings, escaped
                    ▼                            ▼
              js/metrics.js (pure)        store.save ─► localStorage "pr-forge:web:v1"  (the working copy, offline)
              PRs · e1RM · trends · hints        │
                                                 ▼ CLOUD.changed() → debounce
                                         js/sync.js (pure rules) ─► js/cloud.js ─► Supabase
                                            workouts: one row each (id, data, deleted, updated_at stamped by the server)
                                            profile: ONE row of JSON (settings, templates, customs, imports, bodyWeights)  ◄── B1
Sign-in: Google ─► Supabase (implicit flow) ─► #access_token ─► session  (+ handover table for the iPhone sheet)
Offline: sw.js caches the app; data stays in localStorage until sync succeeds.
```

Strengths: logic is pure and tested (`metrics`, `store`, `sync`, `importers`), and the data model is small and readable. Weak spots: `js/app.js` is 2,630 lines with every screen and action in one file; the profile blob (B1); nothing protects a bad deploy (B10).

## 5. Design-system refinements

1. **Declutter the logging card (highest design impact).** Keep Add set and Warm-up visible. Put Swap, Superset, logging type, sides, Move and Remove last set in a "⋯ More" sheet.
2. **Spacing and type as tokens.** Colours are tokens; spacing (6/8/12/16/20) and the type scale are still literal values across `css/app.css`. Make them `--space-*` and `--text-*` variables so the next pass can't drift.
3. **One row pattern.** Settings rows, Needs-attention rows, Exercises rows and Records rows are four near-identical components. Merge them into one (icon / title / subtitle / trailing value / chevron).
4. **Quieter Today stats early in the week.** Show them only once there's a session this week, or replace them with one sentence.
5. **Brand guide:** add the new icons, the change pill, status tiles and chart styles (open from 18 Nov).

## 7. Three-phase roadmap

- **Phase 1 — Trust (1–2 weeks):** B1 sync merge, B2 sign-in address, B3 plausibility check, B5 rest timer, CI, rotate the Google secret.
  - *Done in 2.1.0 (24 Nov):* B1, B3, B5, CI. *Waiting on Kevin:* B2 (Google Cloud return addresses), rotating the secret.
- **Phase 2 — Core experience (2–3 weeks):** logging card "⋯ More", rep and heaviest PRs, session summary after Finish, starter routines on first run.
- **Phase 3 — Polish and depth (later):** design tokens for spacing and type, one row component, custom exercise editing, library clean-up (names, equipment) with an equipment filter, Apple Health export, workout-in-progress sync, IndexedDB if storage grows.

## 8. The 10 highest-impact changes

1. Fix profile sync so two devices can't erase each other's routines (B1).
2. Make Google's sign-in screen name PR Forge's own site (B2).
3. Celebrate rep PRs and heaviest-weight PRs, not only estimated 1RM (B4).
4. A "what changed" summary after each workout, in plain words.
5. Declutter the logging card behind "⋯ More".
6. Catch impossible weights before they become records (B3).
7. Starter routines so a beginner can log within a minute.
8. Rest timer that survives closing the app (B5).
9. Automatic tests on every PR (B10).
10. Rotate the Google client secret (B11).

## Final question: what would stop a serious lifter choosing PR Forge tomorrow?

Not missing features. It already logs as fast as Strong and explains progress more honestly than most. What would stop them is **trust**: a sign-in screen naming a server they've never heard of, a records list that can be wrecked by one typo and that ignores their rep PRs, and the small chance of losing a routine they built on another device. Fix those, calm the logging screen, and PR Forge's honest, plain-word progress becomes the reason to choose it.
